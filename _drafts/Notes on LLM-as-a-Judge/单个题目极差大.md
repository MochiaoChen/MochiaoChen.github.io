# Rubrics 评分时，某个题目的一致性差如何解决？

这是一个很典型的问题,而且恰好在你项目资料中的几篇文献里都有讨论,可以帮你把原因拆解清楚。在拆解之前,先想一个问题:你观察到的「不一致」,具体是指什么层面?是同一个 judge 模型对同一份作业反复打分时分数会跳来跳去(模型自身的不稳定),还是不同的 judge(或人类评分员)之间对同一份作业给出差异很大的分数(评分者间不一致)?这两者的成因不完全相同,但都可能指向同一个题目本身的设计问题。下面按几个层面展开说明。

## 先区分误差来源:评分者内 vs 评分者间

*Standards for Educational and Psychological Testing* (2014版)在讨论信度时明确区分了几类误差来源,这个框架同样适用于 LLM-as-a-Judge:

- **Intrarater reliability(评分者内信度)**:同一个评分者(或同一个 judge 模型)对同一份作品重复打分时的一致程度。如果这个值低,说明问题出在评分过程本身的随机性,而不是评分者之间的标准差异。
- **Interrater reliability(评分者间信度)**:不同评分者(或不同 judge)对同一份作品打分的一致程度。

标准文件里特别提醒了一点:即便 interrater agreement 很高,也不代表 examinee(这里可以类比成「被评估的回答」)在不同任务上的表现是一致的,也就是说,高的评分者间一致性并不能保证题目本身设计得好。反过来,如果某一道题的一致性特别差,而其他题目都还好,那问题很可能出在这道题的**任务设计或 rubric 设计**上,而不是评分机制本身。

## rubric 设计层面可能导致某道题一致性差的原因

结合 Brookhart 的 rubric 设计理论,有几个常见的结构性问题值得你逐一排查:

**1. General rubric 用在了需要 task-specific 判断的题目上。** Brookhart 指出,通用型 rubric(general rubric)的优势是可以跨任务复用、便于学生自评,但代价是「lower reliability at first」,需要更多练习才能用好;而 task-specific rubric 虽然一致性更高,但缺点是「对于开放式任务,好答案如果没有被列在 rubric 里,可能会被判低分」。如果这道题是开放式的(比如允许多种解题路径、多种论证角度),而你用的是笼统的通用标准去套,不同评分者(包括不同的 LLM judge,或同一个 judge 在不同措辞提示下)对「什么算符合标准」的理解就会分叉,这是极差过大的一个常见根源。

**2. 该题目本身处于评分维度的「边界地带」。** 如果某道题的典型回答质量恰好落在两个分数档位之间(比如介于「部分符合」和「基本符合」之间),那么无论是人类评分员还是 LLM judge,都会因为微小的措辞差异或上下文差异而在相邻档位间摇摆。这类边界案例天然比「明显好」或「明显差」的样本更容易产生分歧,极差会显著放大。

**3. Rubric 描述语言含糊,或维度之间存在重叠。** 如果某个评分维度的描述本身就允许多种合理解读(比如「逻辑清晰」这种缺乏具体锚点的表述),不同评分主体对同一份回答会代入不同的隐含标准。Brookhart 强调好的 rubric 需要具体的表现描述(performance descriptions)而不是笼统的形容词堆砌,这一点在 LLM judge 场景下同样成立,甚至更敏感,因为 LLM 会严格按提示词的字面意思去解释标准。

## LLM judge 本身的机制性原因

除了 rubric 设计, 评估的可靠性 $R$ 可表示为三个变量的函数:
$$
R \leftarrow f_R(P_{LLM}, x, C)
$$
其中 $P_{LLM}$ 是模型本身的概率分布,$x$ 是被评估的输入,$C$ 是伴随的上下文(包括 rubric、few-shot 示例等)。这个框架提示我们,某道题一致性差,可能是这三个变量中任意一个出了问题:

- **$P_{LLM}$ 层面**:模型采样时的解码温度(temperature)导致同一提示下多次打分本身就有随机波动;如果该题的回答文本恰好触发了模型的 position bias(判断顺序影响结果)或 length bias(偏好更长的回答),极差也会被放大。
- **$x$ 层面**:如果这道题对应的学生回答本身质量参差不齐、噪声较大(比如包含无关内容、格式混乱),judge 模型更容易误判。
- **$C$ 层面**:如果这道题的 rubric 提示词描述不够具体,或者缺少针对边界情况的锚点示例(anchor examples),模型在缺乏参照的情况下更容易「自由发挥」,导致跨样本、跨评分轮次的判断不稳定。

综述中也提到,评估这类可靠性时常用的定量指标包括 Cohen's Kappa、Spearman's correlation、以及百分比一致性(percent agreement),你如果想量化「这道题到底差到什么程度」,可以对该题单独计算这些指标,和其他题目做横向对比,看看差距具体有多大。

## 面对因为rubric描述语言含糊或维度重叠如何解决



我们面对的第三个问题，即==Rubric 描述语言含糊,或维度之间存在重叠。==解决的核心的思路是:**把「*评价性判断*」换成「*可观察的描述*」**

Brookhart 提出的一个关键区分是「low-inference(低推理)」和「high-inference(高推理)」描述。以「逻辑清晰」为例,这是典型的高推理表述,因为它要求评分者先自己下一个判断,再打分,不同人的判断标准自然不一样。她给的建议不是把所有描述都做到完全客观(那样会失去评判空间,变成琐碎的打勾清单),而是「aim for the lowest-inference descriptors that you can use and still accomplish your purpose」,也就是在保留专业判断空间的前提下,尽量往可观察的方向靠。

比如可以把「逻辑清晰」拆解成类似这样的描述:

- 「基本符合」档位:论点与论据之间存在明确的因果或支持关系,读者不需要补充额外推理即可理解论证链条;

- 「部分符合」档位:论点存在,但至少一处论据与论点之间的关联需要读者自行推断才能成立。

这样写的好处是,评分者(不管是人还是 LLM)判断的对象从「这段论述逻辑清不清晰」这种整体印象,变成了「读者是否需要自行补充推理」这种相对具体的观察点,分歧空间会小很多。

### 技巧一:检查维度是否真正「相互独立」

列出好的评分维度应满足*distinct from one another*,即每个维度对应学习目标的一个独立侧面。如果你的 rubric 里「逻辑清晰」和「论证充分」这两个维度实际上在评分时经常同时升降(比如论证越充分,逻辑自然显得越清晰),这说明两者可能存在重叠,评分者会用同一套判断去填两个格子,这也是极差被放大的常见原因。可以尝试的做法是把两个维度合并成一个,或者明确切开各自负责的观察对象,比如「论证充分」专门看证据数量和相关性,「逻辑清晰」专门看论证的组织顺序和衔接方式。

### 技巧二:确保「跨档位平行」

Feature parallel descriptions from level to level,意思是同一个维度在不同档位的描述,应该针对同一个观察对象在做程度上的区分,而不是每个档位描述完全不同的东西。举个反例:如果「基本符合」写的是「结构完整」,而「部分符合」写的是「用词准确」,这两个描述根本不在同一条轴线上,评分者就没有一个连续的标准可以参照,自然容易在两者之间随意摇摆。你可以逐档检查一下,同一维度的四五个档位描述,是不是都在回答同一个问题(比如「论据与论点的关联强度」),只是强度不同。

### 技巧三:补充锚例(anchor examples),这一条对 LLM judge 尤其重要

Brookhart 强调,好的档位描述应该能够「illustrate those descriptions with examples of students' work」,也就是每个档位最好配一两个真实作答样例作为参照锚点。这一条在人类评分场景里是加分项,但在 LLM-as-a-Judge 场景里几乎是刚需,原因是 LLM 严格按提示词字面意思解释标准,如果只给抽象的文字描述而没有具体锚例,模型在遇到边界样本时缺乏参照,更容易产生批次间的随机波动。实践上,你可以把每个档位的一到两个真实回答样例作为 few-shot 示例直接放进 judge 的提示词里,这也是综述文献里提到的通过丰富上下文 CC C 来提升可靠性 RR R 的一种具体做法。

### 技巧四:用「自下而上」的方式反向修订 rubric

Brookhart 还提到一种 bottom-up 的 rubric 写作路径,大致步骤是:先收集一批真实作答,人工按印象粗分成几档,然后针对每份作答写出「为什么被归到这一档」的具体理由,再从这些理由里提炼出真正区分档位的维度和措辞。这个方法特别适合用来修订你现在这道一致性差的题目,你可以把评分分歧最大的那些边界样本挑出来,看看不同评分者(或 LLM 在不同轮次)给出的判断理由具体差在哪个用词或哪个判断点上,再针对性地把那个模糊的措辞替换成前面说的低推理描述。
